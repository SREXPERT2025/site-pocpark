# Мониторинг поисковых позиций РОСПАРК

## Назначение

Используй этот навык только для отдельного отчета о местах сайта
`https://www.роспарк.рф/` в поисковой выдаче. Не смешивай его с отчетом о
посещениях, Метрике или GA4.

## Обязательные источники

1. Семантическое ядро:
   `reports/seo/rospark_semantic_core_approved_2026-07-30.csv`.
2. История измерений:
   `/Volumes/POCPARK_AI_DATA/POCPARK_SITE_AI/reports/seo/rospark_search_position_history.csv`.
3. В выдаче учитывай только адреса домена `роспарк.рф` и его punycode-вариант
   `xn--80aukedde.xn--p1ai`.

Остановись с блокером, если ядро отсутствует, содержит не 54 строки или хотя бы
одна строка не имеет статуса `approved`. Запросы нельзя дополнять или
переформулировать самостоятельно.

## Чистая выдача

- Используй новый изолированный контекст браузера без авторизации, истории и
  поисковых cookies. Если браузер не позволяет гарантировать изоляцию, пометь
  запуск `blocked_no_private_context` и не выдавай результат за инкогнито.
- Фиксируй регион `Москва`, устройство `desktop`, язык `ru`, страну `RU`.
- Не используй рекламные блоки, подсказки, карты, изображения и AI-ответы как
  органические результаты.
- Проверяй органические результаты последовательно до абсолютной позиции 100.
- Для Google при непрерывной прокрутке считай абсолютный порядковый номер. Номер
  условной страницы вычисляется по десять результатов: позиции 1–10 — страница
  1, 11–20 — страница 2 и так далее.
- Не обходи CAPTCHA, ограничения частоты или защиту поисковика. Запиши статус
  `captcha` или `unavailable` и продолжи со вторым поисковиком после безопасной
  паузы.
- Между запросами делай паузу с небольшим случайным разбросом. Не запускай
  параллельные поисковые вкладки.

## Что измерять

Каждый понедельник и четверг проверяй все 54 утвержденных запроса отдельно в:

- Яндексе;
- Google.

Для каждой пары запрос/поисковик сохрани:

- время по Москве;
- поисковик;
- регион и устройство;
- абсолютную позицию от 1 до 100;
- найденный URL;
- статус `found`, `not_found_top_100`, `captcha` или `unavailable`;
- короткое примечание без cookies, идентификаторов и персональных данных.

## Передача измерений

Сохрани наблюдения в JSON следующего вида:

```json
{
  "measured_at_msk": "2026-08-06T10:00:00+03:00",
  "region": "Москва",
  "device": "desktop",
  "observations": [
    {
      "query": "автоматизация парковок",
      "search_engine": "Yandex",
      "status": "found",
      "position": 14,
      "result_url": "https://www.роспарк.рф/"
    }
  ]
}
```

Затем запусти:

```bash
python3 scripts/build_search_position_report.py \
  --observations <путь-к-json> \
  --history /Volumes/POCPARK_AI_DATA/POCPARK_SITE_AI/reports/seo/rospark_search_position_history.csv \
  --output-dir /Volumes/POCPARK_AI_DATA/POCPARK_SITE_AI/generated/seo_position_reports
```

Сценарий сам проверит запросы по утвержденному ядру, добавит строки в историю и
рассчитает лучшую, предыдущую, текущую позицию и изменение.

## Формат позиции

Пиши однозначно:

`№14 (стр. 2, место 4), было №15, +1, лучшая №11`.

Положительное изменение означает рост к началу выдачи. Если сайт не найден в
первых 100 результатах, пиши `>100`, а не выдумывай позицию 101.

## Личная доставка в MAX

Это отдельный отчет только директору в личный MAX. Запрещено отправлять его в:

- «РОСПАРК ОТДЕЛ ПРОДАЖ»;
- «РОСПАРК общий чат»;
- Telegram;
- клиентские чаты.

После успешной сборки используй только:

```bash
python3 scripts/deliver_search_position_report_personal_max.py \
  --report-path <путь-к-txt> \
  --send \
  --approval recurring-personal-search-position-report
```

Отправитель делит длинный отчет на нумерованные части, проверяет журнал личной
доставки и не отправляет уже подтвержденную часть повторно. После отправки
обязательно проверь для каждой части `status=sent`, `recipient=director_only`,
`max_send_called=true` и наличие `message_id`.
