## 9. Grep

Всегда ограничивай поиск разрешёнными директориями. Не сканируй весь проект, если задача ограничена разделом.

Плохо:

```bash
grep -RIn '100%' app content docs | grep -E 'oborudovanie|keysy'
```

Хорошо:

```bash
grep -RIn -F -i \
  -e '100%' \
  -e 'полностью исключ' \
  'app/(narrow)/oborudovanie' \
  'app/keysy' \
  'content/oborudovanie' \
  'content/keysy' \
  --include='*.tsx' \
  --include='*.ts' \
  --include='*.md' \
  --include='*.mdx'
```

Сначала ограничивай директории, потом ищи.

Если общий компонент включается в grep только потому, что он используется разрешённой страницей, явно отделяй:

1. строгий scope маршрутов и content;
2. связанные компоненты для второго этапа проверки;
3. файлы, которые нельзя менять без подтверждения file-scope.

Строгий первый grep — только по маршрутам и content:

```bash
grep -RIn -F -i \
  -e '100%' \
  -e 'полностью исключ' \
  -e 'безотказная система' \
  -e 'окупаемость' \
  -e 'увеличить доходность' \
  -e 'гарантированно' \
  -e 'мгновенно' \
  'app/(narrow)/oborudovanie' \
  'app/keysy' \
  'content/oborudovanie' \
  'content/keysy' \
  --include='*.tsx' \
  --include='*.ts' \
  --include='*.md' \
  --include='*.mdx'
```

Второй этап — только после подтверждения, что компонент реально используется разрешёнными страницами:

```bash
grep -RIn -F \
  -e 'EquipmentCard' \
  -e 'ProductCard' \
  -e 'ProjectCard' \
  -e 'ProjectsControls' \
  -e 'CatalogControls' \
  'app/(narrow)/oborudovanie' \
  'app/keysy' \
  --include='*.tsx' \
  --include='*.ts'
```

Если компонент найден, его можно добавить в список связанных файлов-кандидатов, но не считать разрешённым к правке без отдельного подтверждения file-scope.

Если после второго этапа нужно проверить сами связанные компоненты, делай это отдельной командой и явно помечай как “связанные компоненты, не утверждённые к правке”:

```bash
grep -RIn -F -i \
  -e '100%' \
  -e 'полностью исключ' \
  -e 'безотказная система' \
  -e 'окупаемость' \
  -e 'увеличить доходность' \
  -e 'гарантированно' \
  -e 'мгновенно' \
  'app/components/catalog/EquipmentCard.tsx' \
  'app/components/catalog/CatalogControls.tsx' \
  'app/components/ui/ProductCard.tsx' \
  'app/components/ui/ProjectCard.tsx' \
  'app/components/projects/ProjectsControls.tsx' \
  --include='*.tsx' \
  --include='*.ts'
```

Для списков файлов-кандидатов используй:

```bash
mkdir -p tmp

grep -RIl -F -i \
  -e 'искомая фраза' \
  'разрешённая/директория' \
  --include='*.tsx' \
  --include='*.ts' \
  --include='*.md' \
  --include='*.mdx' \
| sort -u | tee tmp/candidate_files.txt
```

Если используешь `tmp/candidate_files.txt`, сначала добавь `mkdir -p tmp`.

## 21. Мобильная проверка

Любая правка видимого блока требует проверки ширин:

```text
360 px
390 px
400 px
430 px
768 px
```

Проверить:

- нет горизонтального скролла;
- заголовки не обрезаются;
- кнопки помещаются;
- формы не шире экрана;
- поля формы не обрезаются;
- текст не прилипает к краям;
- карточки не вылезают за экран;
- мобильное меню работает;
- CTA не превращается в тяжёлую стену текста.

Проверка горизонтального скролла:

```js
document.documentElement.scrollWidth > document.documentElement.clientWidth
```

Ожидаемо:

```text
false
```
