Дата: 2026-05-03

## Назначение

Документ описывает, каких ИИ-агентов целесообразно использовать для развития сайта РОСПАРК, какие задачи им давать и какие ограничения соблюдать.

## Общая идея

Сайт нужно развивать не одним универсальным агентом, а небольшой командой ролей. Каждая роль отвечает за свою часть: архитектуру, тексты, маркетинг, SEO/GEO, код и проверку.

## Роли

## 1. Site Architect

### Зона ответственности

- структура сайта;
- карта страниц;
- маршруты;
- компоненты;
- связи между страницами;
- безопасность изменений;
- постановка задач frontend-кодеру.

### Что должен знать

- `docs/site/SITE_STRUCTURE.md`;
- `docs/site/ARCHITECTURE.md`;
- свежий `project_full_dump.txt`;
- текущие правила деплоя;
- список критичных страниц.

### Типовые задачи

```text
Проверь, какие файлы нужно изменить для добавления раздела "Новости".
```

```text
Составь безопасное ТЗ на добавление новой страницы решения для бизнес-центров.
```

```text
Проверь, не ломает ли новая секция мобильную версию.
```

## 2. Marketing Strategist

### Зона ответственности

- позиционирование;
- офферы;
- структура коммерческих страниц;
- сегменты аудитории;
- логика конверсии;
- тексты первого уровня.

### Что должен знать

- `docs/marketing/POSITIONING.md`;
- `docs/content/CONTENT_STYLE_GUIDE.md`;
- карту сайта;
- реальные направления бизнеса РОСПАРК.

### Типовые задачи

```text
Проанализируй страницу /resheniya/torgovye-centry и предложи усиление оффера для управляющей компании ТЦ.
```

```text
Составь структуру новой страницы для платной парковки у бизнес-центра.
```

## 3. Russian B2B Editor

### Зона ответственности

- русский деловой стиль;
- удаление лишних иностранный слов;
- повышение ясности;
- снижение рекламного шума;
- сохранение смысла без технических искажений.

### Что должен знать

- `docs/content/CONTENT_STYLE_GUIDE.md`;
- текущие тексты сайта;
- целевую аудиторию.

### Типовые задачи

```text
Проведи редактуру текста: убери англицизмы, сохрани инженерный смысл, сделай текст понятным директору УК.
```

```text
Составь таблицу: текущая формулировка / проблема / новая формулировка.
```

## 4. SEO/GEO Analyst

### Зона ответственности

- поисковая структура;
- страницы под Яндекс/Google;
- страницы под ИИ-поиск;
- FAQ;
- Answer-first блоки;
- структурированные данные;
- внутренняя перелинковка.

### Что должен знать

- карту сайта;
- стратегию GEO;
- контентные правила;
- приоритетные направления бизнеса.

### Типовые задачи

```text
Подготовь GEO-структуру страницы "Автоматизация парковки для торгового центра".
```

```text
Предложи FAQ-блок для страницы оборудования без перегруза коммерческого текста.
```

## 5. Frontend Coder

### Зона ответственности

- Next.js;
- TypeScript;
- Tailwind CSS;
- компоненты;
- адаптивная верстка;
- безопасные патчи;
- сборка.

### Ограничения

- не менять API форм без отдельного задания;
- не трогать `.env`;
- не ломать мобильные ширины;
- не добавлять лишние зависимости без согласования;
- после изменений обязательно `npm run build`.

### Типовые задачи

```text
Внеси правки только в указанные файлы, сохрани мобильную адаптацию 375–430 px.
```

```text
Подготовь patch-архив с изменёнными файлами.
```

## 6. QA Mobile Checker

### Зона ответственности

- ручная проверка мобильной версии;
- поиск горизонтального скролла;
- проверка карточек, форм, меню;
- проверка критичных страниц после изменений.

### Чеклист

- нет горизонтального скролла;
- заголовки не выходят за карточки;
- карточки не ломают layout;
- формы помещаются;
- кнопки доступны;
- меню открывается и закрывается;
- длинные слова переносятся;
- картинки не раздвигают страницу.

## Рекомендуемый процесс работы

```text
1. Site Architect определяет область изменения.
2. Marketing Strategist формирует смысловую задачу.
3. Russian B2B Editor готовит текст.
4. SEO/GEO Analyst добавляет поисковую структуру, если нужно.
5. Frontend Coder вносит изменения.
6. QA Mobile Checker проверяет результат.
7. После успешной проверки — commit, tag, deploy.
```

## Правила передачи контекста агентам

Каждому агенту передавать:

1. цель задачи;
2. список файлов, которые можно менять;
3. список файлов, которые нельзя менять;
4. актуальный dump или нужный фрагмент проекта;
5. критерии приёмки;
6. ограничения по мобильной версии;
7. запрет на лишние изменения.

```text

TASK: <short task name>
MODE: <analysis | content | code | qa-review>
STATUS: ready-for-work

Контекст:
...

Можно менять:
- ...

Нельзя менять:
- ...

Требуется:
1. ...
2. ...
3. ...

Критерии приёмки:
- npm run build проходит;
- мобильная ширина 375–430 px без горизонтального скролла;
- формы работают;
- смысл текста сохранён;
- лишние файлы не изменены.
```

## Актуальный регламент субагентов

С 2026-07-06 рабочая структура AI-команды уточнена в отдельном документе:

- `docs/agents/AI_TEAM_ORCHESTRATION.md`

Project-scoped профили субагентов лежат в:

- `.codex/agents/rospark-ai-architect.toml`
- `.codex/agents/rospark-ai-marketer.toml`
- `.codex/agents/rospark-tech-editor.toml`
- `.codex/agents/rospark-ai-designer.toml`
- `.codex/agents/rospark-frontend-coder.toml`
- `.codex/agents/rospark-qa-tester.toml`

Главное правило: постоянные субагенты работают read-only. Они анализируют,
готовят ТЗ и проверяют риски. Кодовые изменения выполняются только после
утверждённого scope, в отдельной ветке от фактически проверенной и отдельно
согласованной базовой ветки, с diff, проверками и review Архитектора.
