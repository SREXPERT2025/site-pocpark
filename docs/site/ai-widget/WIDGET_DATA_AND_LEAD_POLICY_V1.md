# AI-виджет — data, consent и lead policy v1

Дата: 2026-07-27, production-дополнение 2026-07-28
Статус: утверждённая продуктовая схема; юридический текст проверяется перед
публичным cutover.

## 1. Три независимых режима

### Справочный диалог

- контакт не требуется;
- согласие на передачу лида не требуется;
- пользователь может продолжать задавать вопросы анонимно;
- полная история не передаётся в Метрику и MAX.

### Обезличенная аналитика

Допускаются только события без текста диалога и PII:

- открытие виджета;
- первый вопрос как факт события;
- тип маршрута `faq`, `rag`, `model`, `fallback`;
- задержка;
- переход на страницу или demo;
- начало и завершение consent flow;
- подтверждённое создание лида;
- код безопасной ошибки.

Запрещены имя, телефон, email, госномер, свободный текст и полный transcript.

### Передача обращения

Начинается только после прямой просьбы пользователя:

- подготовить расчёт;
- связаться;
- передать вопрос менеджеру;
- оформить обращение.

## 2. Минимальная карточка

Обязательны:

- имя;
- объект или тип объекта;
- содержательная задача;
- проверяемый контакт;
- отдельное `consent: true`;
- версия и время согласия;
- источник страницы;
- idempotency key.

Имя подтверждено директором как обязательное для реальной карточки. Оно
запрашивается только после намерения оформить обращение и используется для
вежливого общения. Для справочного диалога представляться не обязательно.

Production tool использует отдельный `POST /api/ai-widget/lead`, существующий
lead registry, idempotency key и MAX outbox. Он включается только одновременно
с журналом, live handoff, рабочим реестром и production gateway.

## 3. Текст согласия-кандидат

> Подтверждаю передачу указанных мной контактных данных и описания задачи ООО
> «СР Эксперт» для обработки обращения и связи со мной. Я ознакомлен(а) с
> Политикой обработки персональных данных и могу отозвать согласие.

Интерфейс должен:

- показать краткое резюме перед подтверждением;
- дать ссылки на `/privacy` и
  `/soglasie-na-obrabotku-personalnyh-dannyh`;
- не считать продолжение диалога согласием;
- не подставлять `true` автоматически;
- записывать версию согласия, например `ai-widget-lead-v1`.

## 4. Подтверждённые сроки

| Данные | Срок / правило |
|---|---|
| Активная анонимная сессия | 24 часа |
| Полный transcript preview или production | Отдельная SQLite, доступ только Андрею и Сергею, максимум 7 дней |
| Operational logs | До 14 дней, без PII и текста сообщений |
| Обычный переданный лид | 60 дней — действующий контракт lead registry |
| Demo feedback | 30 дней — действующий контракт |
| Анонимная аналитика | По действующей политике аналитики, без PII |

Сроки подтверждены директором 2026-07-27.

Для production хранение диалога используется для контроля качества и связи с
добровольной заявкой. Посетитель видит уведомление о сроке и ссылку на
политику. Имя и телефон хранятся только в lead registry и не копируются в
таблицы диалога.

## 5. Владельцы и доступ

- владелец данных и пилота — ООО «СР Эксперт», ответственное решение принимает
  Андрей как директор;
- рабочий пользователь реестра — Сергей, РОП;
- Андрей и Сергей видят все preview- и production-диалоги;
- Андрей может удалять диалог безвозвратно;
- Сергей может просматривать и выгружать диалоги, но не удалять их и не менять
  retention или режим публикации;
- модель не имеет права читать реестр лидов;
- RAG не содержит обращений пользователей;
- модель не получает результат регистрации лида: форму и подтверждение
  полностью обслуживает VPS.

## 6. MAX

- `AI-WIDGET-0`, `AI-WIDGET-1` и `AI-WIDGET-2` не отправляют сообщения в MAX;
- production-заявка ставится в существующий MAX outbox;
- сообщение создаётся из принятой карточки, а не из полного transcript;
- отправка выполняется через существующий outbox;
- ответ пользователю о передаче разрешён только после durable result;
- повторная отправка защищается idempotency key;
- первая контрольная отправка выполняется отдельно после проверки отсутствия
  старого backlog и разрешается ровно для одной заявки.

## 7. Удаление и отзыв

Пользователь может обратиться по контактам из `/privacy`.

До публичного cutover нужно проверить:

- поиск записи по безопасному идентификатору;
- удаление лида и связанных данных по существующей процедуре;
- отсутствие PII в аналитике и operational logs;
- удаление test transcripts;
- фиксацию действия в audit log без копирования удаляемого текста.

## 8. Закрытые этапы

### AI-WIDGET-1

- только синтетические данные;
- локальный CRM-симулятор;
- никаких внешних отправок;
- transcript используется только для тестовой проверки.

### AI-WIDGET-2

- непубличный UI;
- тестовые контакты;
- отдельный session/rate-limit contour;
- handoff остаётся симуляцией;
- server-side журнал хранит вопрос, ответ, маршрут, длительность и связанную
  тестовую карточку не более семи дней;
- тестовая карточка всегда помечена `ТЕСТ`, не попадает в production registry
  и не отправляется в MAX;
- будущий текст MAX доступен для проверки внутри служебного журнала.

### AI-WIDGET-3

Только после отдельного подтверждения:

- ограниченный реальный трафик;
- реальный lead tool;
- consent v1;
- 60-дневный retention;
- MAX через outbox;
- ежедневный review без передачи transcript в общий чат.

### AI-WIDGET-4

- публичный VPS API работает только с разрешённого origin;
- production gateway на Mac Studio отделён от preview;
- имя и телефон принимает отдельная форма VPS;
- заявка регистрируется только после отдельного consent;
- transcript хранится до семи дней, лид — до 60 дней;
- persistent rate limit и аварийный fallback обязательны;
- публичный интерфейс не маркируется как тестовый;
- первая отправка в MAX остаётся отдельным операционным gate.

## 9. Роли временного кабинета и будущая CRM

- все новые рабочие заявки видны Андрею и Сергею одновременно;
- ответственный по умолчанию — Сергей, РОП;
- Андрей сохраняет полный административный контроль и удаление;
- Сергей обрабатывает, закрывает и выгружает без удаления;
- временный кабинет не развивается в самостоятельную CRM;
- после `CRM-INTEGRATION-001` amoCRM становится рабочей системой распределения
  между менеджерами;
- в amoCRM передаётся карточка и краткое резюме, а полный transcript остаётся
  во внутреннем журнале РОСПАРК.
