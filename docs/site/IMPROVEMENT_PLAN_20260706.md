## 2. Найденные технические хвосты

### P0.1. Убрать tracked-файлы-дубликаты `— копия`

В `app/` отслеживаются файлы с именами `— копия`. Они выглядят как случайные локальные копии компонентов:

- `app/(narrow)/oborudovanie/[slug]/ProductView.tsx — копия`
- `app/(narrow)/resheniya/dlya-rukovoditeley/components/Solution.tsx — копия`
- `app/(narrow)/resheniya/dlya-sluzhby-bezopasnosti/components/Solution.tsx — копия`
- `app/components/FeaturesShowcase.tsx — копия`
- `app/components/FeaturesShowcase.tsx — копия 2`

Риск: такие файлы засоряют сборку, усложняют поиск и могут случайно попасть в импорт или будущий diff.

Действие: сравнить с актуальными компонентами, убедиться что они не импортируются, затем удалить отдельным маленьким коммитом.

Проверки: `rg` по импортам, `npm run typecheck`, `npm run build`, `git diff --check`.

### P0.2. Проверить текущий build после цепочки merge

Последние отчеты фиксируют успешные сборки по отдельным веткам, но текущая ветка уже содержит несколько объединенных задач.

Действие: запустить `npm run typecheck` и `npm run build` именно на текущей ветке.

Риск: низкий, код не меняется.

### P0.3. Smoke-проверка форм на demo

Перед production нельзя считать лидогенерацию готовой без ручного smoke.

Проверить:

- `/contacts` -> `/api/lead`;
- `/quiz` -> `/api/lead`;
- получение заявки в согласованный канал;
- отсутствие PII в analytics events.

Production deploy не выполнять без отдельного подтверждения.

## 3. Ближайшие улучшения сайта

### P1.1. Главная страница: hygiene pass

Текущая ветка уже названа под homepage hygiene, поэтому это хороший следующий фокус.

Проверить и улучшить:

- первый экран: ясность оффера, CTA, мобильная высота;
- логика блоков: возможности -> типы объектов -> роли -> коммерческий блок -> форма;
- повторяемость CTA и внутренних ссылок;
- отсутствие тяжелых декоративных элементов и лишних обещаний;
- изображения и видео: загрузка, alt, мобильное поведение.

Ограничение: не менять формы/API, аналитику, sitemap и глобальную навигацию в этом же diff.

### P1.2. Навигационные связки solution -> equipment -> cases -> quiz

Добавить аккуратные внутренние переходы на ключевых страницах:

- страницы решений ведут к релевантному оборудованию;
- оборудование ведет к подходящим кейсам и квизу;
- кейсы ведут к похожим решениям и заявке.

Цель: усилить SEO/GEO и путь пользователя без расширения верхнего меню.

### P1.3. Feature pages `/vozmozhnosti/*`

Усилить страницы возможностей:

- answer-first блок;
- FAQ и FAQPage schema, где есть реальные вопросы;
- Breadcrumb schema;
- ссылки на решения, оборудование и кейсы.

Ограничение: не выдумывать характеристики, цены, гарантии или неподтвержденные сценарии.

### P1.4. Кейсы: нормализовать frontmatter

Для 30 кейсов постепенно добавить структурированные поля:

- city;
- region;
- objectType;
- equipment;
- result facts;
- related solution links.

Цель: улучшить внутреннюю фильтрацию, schema и AI-search.

### P1.5. 404 recovery page

Создать `app/not-found.tsx` с полезными ссылками:

- решения;
- оборудование;
- кейсы;
- контакты;
- квиз.

Цель: не терять пользователя при ошибочной ссылке.

## 6. Рабочий протокол

- Каждая задача — отдельная ветка или аккуратный отдельный diff в текущей feature-ветке.
- Не трогать `main` напрямую.
- Не делать production deploy без отдельного явного подтверждения.
- Перед правкой фиксировать scope и файлы.
- После правки запускать минимум `npm run typecheck`, для UI/SEO-изменений также `npm run build`.
- Для визуальных изменений проверять desktop и mobile.
