# РОСПАРК - процесс подготовки статьи по новости

Дата: 2026-07-06  
Статус: рабочий процесс после первого тестового материала.

## Цель

Делать не новостную ленту ради частых публикаций, а экспертные материалы: новость рынка -> контекст -> выводы для владельцев парковок, ТЦ, БЦ, ЖК, складов и операторов.

## Роли

### 1. Маркетолог-исследователь

Задача:

- найти яркие и обсуждаемые новости в парковочной сфере России;
- проверить официальный источник;
- оценить новость по практической пользе;
- выбрать тему с понятной связью с экспертизой РОСПАРК.

Критерии отбора:

- новость связана с парковками, оплатой, шлагбаумами, доступом, городским транспортом, девелопментом, ТЦ, БЦ, ЖК, складами, ЭЗС или безопасностью;
- есть официальный источник или надежное деловое/отраслевое СМИ;
- можно сделать практический вывод для B2B-аудитории;
- нет риска пересказать слух или конфликт без фактов.

### 2. AI-копирайтер

Задача:

- превратить новость в экспертную статью;
- отделить факт новости от комментария РОСПАРК;
- добавить answer-first блок;
- написать H2-структуру, FAQ и внутренние ссылки.

Рабочий промпт:

- `docs/agents/ai-copywriter/ROSPARK_AI_COPYWRITER_PROMPT.md`

### 3. Контент-редактор

Задача:

- проверить стиль;
- убрать рекламный нажим;
- проверить, что нет выдуманных цен, гарантий, клиентов, характеристик и сертификатов;
- проверить, что статья полезна как самостоятельный материал.

### 4. QA / SEO-GEO проверка

Задача:

- проверить source URL;
- проверить даты, цифры, названия ведомств и компаний;
- проверить внутренние ссылки;
- проверить Article JSON-LD, FAQ JSON-LD, sitemap, canonical;
- проверить, что CTA ведет в квиз с релевантным заголовком.

### 5. Кодер-разработчик

Задача:

- добавить markdown-файл в `content/stati`;
- при необходимости добавить source mapping в `app/(narrow)/quiz/page.tsx`;
- запустить `npm run typecheck`, `npm run build`, `git diff --check`;
- обновить внешний preview-сервер.

## Формат статьи

1. Факт новости: что произошло, где, когда, кто сообщил.
2. Контекст: почему это важно для рынка.
3. Экспертный разбор: что это значит для владельцев объектов.
4. Практический чек-лист.
5. Ограничения: что неизвестно и что нельзя утверждать.
6. Внутренние ссылки на решения, возможности, оборудование и квиз.

## Первый тестовый материал

Источник:

- Официальный сайт «Московского паркинга», 29.06.2026: функция исправления ошибок при оплате парковки в приложении «Парковки России» использовалась более 1,7 млн раз с начала года, рост на 54% к аналогичному периоду прошлого года.

Материал на сайте:

- `/stati/ispravlenie-oshibok-oplaty-parkovki`

Почему тема подходит:

- есть официальный источник;
- тема связана с цифровой оплатой парковки;
- есть практический вывод для коммерческих парковок: нужны сценарии исправления ошибок, журнал событий и роли операторов;
- статья не утверждает, что РОСПАРК связан с городским сервисом.

## Что автоматизировать позже

Если тестовый процесс принят:

1. Создать skill `parking-news-article`.
2. Раз в 3 дня запускать поиск новостей.
3. Готовить черновик статьи и отчет.
4. Не публиковать автоматически без review, если статья содержит юридические, ценовые, тарифные, конфликтные или неподтвержденные факты.
