Не начинать большую перестройку сайта.


Каждая правка — маленькая задача, отдельный diff, build, review, commit, push.

## 2. P0 — сделать перед production обязательно

### P0.1. Проверить и исправить ссылки на `/resheniya`

**Проблема:** маркетолог отметил, что на ряде страниц может быть ссылка `← Все решения РОСПАРК` с href `/resheniya`, но отдельной страницы `/resheniya` в структуре может не быть.

**Почему важно:** если пользователь после чтения страницы уходит по “Все решения” и получает 404, сайт выглядит недособранным.

**Что сделать:**

1. Дать frontend-разработчику audit-only задачу:

```text
TASK: DEV-PROD-RESHENIYA-INDEX-LINKS-AUDIT-001
STATUS: audit-only-no-code-change

Найти все href="/resheniya" и ссылки на /resheniya.
Проверить, существует ли реальная страница /resheniya.
Код не менять.
Дать список файлов и рекомендацию:
- создать /resheniya;
- или заменить ссылки на рабочие страницы;
- или оставить, если маршрут реально существует.
```

2. После аудита принять архитектурное решение.

**Предпочтительный быстрый вариант:** если `/resheniya` действительно отсутствует, временно заменить ссылки “Все решения” на `/` или на наиболее релевантную рабочую страницу.  
**Более правильный вариант:** создать обзорную страницу `/resheniya`, но это уже чуть больше scope.

### P0.2. Убрать служебный черновой текст со страницы `/resheniya/sravnenie-podhodov`

**Проблема:** маркетолог нашёл публичный текст в CTA-блоке страницы сравнения подходов:

```text
ООО "СР Эксперт" используется в футере сайта и на специализированных страницах…
```

**Почему важно:** это выглядит как внутренняя заметка разработчику и ломает доверие.

**Файл-кандидат:**

```text
app/(narrow)/resheniya/sravnenie-podhodov/components/CallToAction.tsx
```

**Решение:** удалить служебный текст и заменить нормальным доверительным дисклеймером:

```text
Работаем как ООО «СР Эксперт». Подготовим предварительную конфигурацию, состав оборудования и следующий шаг по проекту.
```

**Задача разработчику:**

```text
TASK: DEV-PROD-SRAVNENIE-CTA-DRAFT-TEXT-FIX-001
STATUS: ready-for-dev

Разрешено менять только:
app/(narrow)/resheniya/sravnenie-podhodov/components/CallToAction.tsx

Цель:
Удалить внутренний служебный текст из видимого CTA и заменить на согласованный доверительный дисклеймер.

Не менять:
формы, API, маршруты, metadata, JSON-LD, ExtendedInfo, FAQ, navigation, Header, MobileMenu, sitemap.

После правки:
git diff --name-only
npm run build
Commit не делать до review Архитектора.
```

### P0.3. Привести контактные данные к единой логике

**Проблема:** маркетолог отметил расхождение: на странице контактов указан `is@srexpert.su`, а в `siteConfig` публичным коммерческим email может быть `sales@rospark.ru`.

**Почему важно:** разные email на сайте снижают доверие B2B-клиента.

**Что сделать сначала:** не менять код сразу. Андрей должен подтвердить, какой email основной.

**Решение, которое выглядит логичным:**

```text

is@srexpert.su — только если нужен как юридический/технический адрес, с понятной подписью.
```

**Задача разработчику после решения владельца:**

```text
TASK: DEV-PROD-CONTACTS-CONSISTENCY-AUDIT-001
STATUS: audit-only-no-code-change

Найти все email, телефоны и юр. контактные данные в app/config/site.ts, contacts page, footer, forms, metadata/microdata если есть.
Код не менять.
Дать таблицу:
файл / текущий контакт / где виден / рекомендация.
```

После аудита — отдельная маленькая правка.

### P1.4. Добить оставшиеся рискованные обещания

Редактор отметил, что после P1-чистки могут оставаться спорные фразы:

```text
рост NOI на 15–30%
аудит и расчёт за 1 день
без персонала
полный контроль
без человеческого фактора
мгновенная оплата
идеальный клиентский путь
полностью освободилась
```

**Важно:** часть этих фраз может быть в metadata, ExtendedInfo или SEO/GEO. Не править всё подряд.

**Порядок:**

1. audit-only grep по видимым TSX/MD;
2. отдельно audit-only по metadata/content/extended;
3. маркетолог/редактор дают замены;
4. архитектор утверждает file-scope;
5. только потом разработчик правит.

**Примеры безопасных замен:**

```text
рост NOI на 15–30% → потенциал роста доходности зависит от объекта, трафика и тарифной модели
аудит и расчёт за 1 день → предварительная оценка — от 1 рабочего дня после получения исходных данных
без персонала → снижение зависимости от постоянного ручного контроля
полный контроль → управляемый контроль
без человеческого фактора → меньше ручных операций и спорных решений
мгновенная оплата → быстрая безналичная оплата
идеальный клиентский путь → понятный сценарий проезда и оплаты
полностью освободилась → существенно снизилась доля посторонних автомобилей
```

## 4. P1/P2 — не блокеры, но важно не забыть

### 4.1. Страница “Складские комплексы” слабее остальных решений

Маркетолог считает, что `/resheniya/skladskie-kompleksy` выглядит слабее страниц ТЦ, БЦ и ЖК.

**Перед production:** не обязательно полностью переписывать, если времени мало.  
**Минимум:** проверить, что страница не выглядит черновиком и есть понятный следующий шаг.

**После production:** усилить страницу структурой:

1. Hero: автоматизация проезда для складов и логистических комплексов;
2. проблемы: очереди на КПП, подрядчики, окна проезда, ручные пропуска;
3. сценарии: персонал, арендаторы, подрядчики, грузовой транспорт;
4. что внедряется: распознавание номеров, RFID, QR, журналы, роли;
5. финальный CTA + форма.

### 4.2. Раздел `/vozmozhnosti` может выглядеть как набор слайдов

**Проблема:** маркетолог считает, что разделу не хватает вступления и понятной маршрутизации.

Можно после production, если нет времени.

### 4.4. CTA на сайте нужно привести к единой системе

Маркетолог отметил, что на страницах встречаются разные CTA:

```text

Получить консультацию
```

### 4.5. ExtendedInfo на ролевых страницах стоит рано

## 7. GO / NO-GO критерии

### GO на production возможен, если:

- `npm run build` проходит;
- demo поднялся;
- основные страницы открываются;
- нет 404 на важных страницах;
- формы `/contacts` и `/quiz` отправляют заявки;
- заявки реально приходят;
- нет критичных битых картинок;
- нет служебного текста на публичных страницах;
- нет ссылки на несуществующую `/resheniya`;
- контакты не противоречат друг другу или противоречие осознанно принято владельцем.

### NO-GO, если:

- не работает build;
- не работает PM2/demo;
- не отправляются заявки;
- есть 404 из меню или CTA;
- на видной странице остался служебный черновой текст;
- основные изображения битые;
- мобильная версия критично ломается.

## 10. Короткий итог для старта следующего дня

Начинаем не с новых текстов, а с production-readiness:

