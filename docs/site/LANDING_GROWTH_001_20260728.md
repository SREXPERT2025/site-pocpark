# LANDING-GROWTH-001 — упрощённые посадочные РОСПАРК

Дата: 28.07.2026

Статус: read-only аудит принят как направление; код, preview, production,
реклама и sitemap этим документом не изменяются.

## 1. Задача

Основной сайт РОСПАРК сохраняется как подробный экспертный ресурс. Для
посетителей, которые впервые выбирают автоматизацию парковки и мыслят
знакомыми категориями «шлагбаум, камера, оплата, пропуск», нужен отдельный
короткий вход:

```text
понятная проблема
→ простой сценарий
→ доказательство на реальных объектах
→ расчёт проекта
→ заявка
```

Первая посадочная не заменяет главную страницу и не публикуется как статья.

## 2. Проверенный исходный пакет

В Downloads находятся:

- `лендинг/ROSPARK_MINILANDING_SOURCE.zip`;
- `лендинг/ROSPARK_MINILANDING_HANDOFF.md`.

Пакет содержит:

- готовую React/Next.js страницу;
- desktop/mobile композицию;
- реальные изображения объектов и кейсов;
- схему «камера видит номер → клиент оплачивает → шлагбаум открывается»;
- интерактивные карточки четырёх типов объектов;
- ссылки на существующие кейсы и `/quiz`;
- видео и локальные шрифты.

Полный runtime пакета не является drop-in зависимостью основного сайта:

- пакет использует Next.js 16, React 19, Vinext/Vite и Cloudflare tooling;
- production-сайт использует Next.js 14.2.35;
- `globals.css` содержит глобальные `body`, `a`, `img`, CSS variables и общие
  классы, которые при прямом копировании могут изменить весь сайт.

Следовательно, переносится визуальная страница, компоненты и assets, а не
`package.json`, worker, auth, hosting-конфигурация или отдельный runtime.

## 3. Предлагаемая архитектура

Первый route:

```text
/proshche
```

Страница создаётся вне узкого `(narrow)` layout, чтобы сохранить full-width
композицию, но наследует root layout основного сайта:

- общий Header и Footer;
- AI-консультант;
- cookie consent;
- Яндекс Метрику и GA4;
- действующий `/quiz`;
- существующий lead registry и MAX outbox.

Стили нужно ограничить namespace/CSS module. Assets размещаются в отдельном
каталоге основного сайта и проходят оптимизацию.

## 4. Конверсионный контракт

Первый пилот использует:

- CTA на относительный URL `/quiz?source=landing-proshche-v1`;
- отдельный безопасный `landing_group` для аналитики;
- события без PII:
  `landing_view`, `landing_cta`, `quiz_start`, `form_success`;
- существующее явное согласие формы;
- существующую доставку лида Сергею и в MAX.

Нельзя передавать в аналитику телефон, имя, свободный текст сообщения, полный
query string или динамический URL.

## 5. SEO-решение

На preview страница остаётся `noindex`.

Перед production нужно отдельно выбрать:

1. индексируемая уникальная посадочная с self-canonical;
2. временная рекламная `noindex, follow` страница;
3. отложенная публикация до готовности уникального текста и доказательств.

Не помещать страницу в `/stati`: у неё коммерческий intent, CTA и
конверсионная воронка. Не создавать 5–10 дублей одного шаблона с заменой
ключевого слова.

Будущие темы формируются по отдельным болям, например:

- парковка без ручной работы охраны;
- контроль доступа постоянных сотрудников;
- оплата без очередей;
- гостевой доступ;
- замена старой парковочной системы;
- парковка бизнес-центра или ЖК.

## 6. UX-вход с основного сайта

Первый пилот не использует автоматическое модальное окно. На странице уже
работают AI-консультант и cookie banner, поэтому ещё один плавающий слой
увеличивает риск перегрузки и конфликтов на мобильном экране.

После приёмки `/proshche` проверить ненавязчивый вход:

- inline-карточка после первого экрана главной;
- текст «Впервые выбираете парковочную систему?»;
- CTA «Показать, как это работает»;
- однократный dismissible вариант только после отдельного UX-теста.

## 7. Риски до реализации

1. Глобальные стили исходника могут конфликтовать с основным сайтом.
2. Видео `payment-demo.mp4` около 2.5 MB и два JPEG около 1.7–1.8 MB требуют
   оптимизации, poster/lazy loading и performance budget.
3. Утверждение `50+ городов` нужно подтвердить через claim ledger.
4. Интерактивному dialog нужны focus return/focus trap, Escape, scroll lock и
   keyboard QA.
5. Абсолютные ссылки на Unicode-домен нужно заменить относительными.
6. Нужны metadata, Open Graph, canonical и отдельное решение о sitemap.
7. Нужна visual QA на `320/375/390` и desktop, включая отсутствие конфликта
   с AI-виджетом и cookie banner.

## 8. Порядок реализации

1. Зафиксировать route и SEO-режим preview.
2. Перенести страницу в отдельную feature-ветку без runtime исходного пакета.
3. Изолировать стили и адаптировать assets.
4. Подключить существующий quiz/source и privacy-safe события.
5. Выполнить typecheck, lint, production build и целевые тесты.
6. Показать Mac Studio preview владельцу на desktop/mobile.
7. Исправить замечания и получить отдельную визуальную приёмку.
8. Только затем решить вход с главной, sitemap/indexation и накопительный
   production release.

## 9. Критерий готовности пилота

- основной сайт визуально и функционально не изменён вне нового route;
- `/proshche` объясняет предложение без технической перегрузки;
- CTA открывает правильный quiz source;
- аналитика не содержит PII;
- AI-консультант и cookie banner не перекрывают ключевые действия;
- страница доступна с клавиатуры и без горизонтального overflow;
- все публичные утверждения подтверждены;
- владелец принял desktop и mobile preview.
