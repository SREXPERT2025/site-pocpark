# AI-WIDGET-1 — технический дизайн закрытого стенда

Дата: 2026-07-27
Статус: UI/API-каркас и loopback gateway готовы локально, runtime не включён.
Размещение: Mac Studio, preview `srtestrealme.ru:3001`.

## 1. Проверенная исходная точка

- `https://srtestrealme.ru:3001/demo` отвечает `200`;
- preview имеет `noindex`, `no-store` и security headers;
- HTTP authentication на всём preview отсутствует;
- `noindex` не является контролем доступа;
- существующий `TEST/TEST` относится к продуктовой demo-авторизации, а не к
  служебному доступу AI-пилота;
- маршрута `/demo/ai-konsultant` и AI API сейчас нет.

## 2. Подтверждённый формат пилота

```text
любая страница preview-сайта
→ плавающая кнопка справа снизу
→ боковая панель диалога
→ /api/demo/ai-widget/chat
→ restricted gateway на loopback Mac Studio
→ deterministic route / FAQ / Fact Gate
→ локальный Qwen3.6-27B
```

Браузер не получает адрес Ollama, gateway secret, системный prompt или файлы
базы знаний.

## 3. Доступ на коротком preview-пилоте

Директор подтвердил пилот без дополнительной авторизации:

- без длинной служебной ссылки;
- без отдельной страницы AI-консультанта;
- без логина и пароля внутри виджета;
- виджет показывается на preview-сайте только при включённом feature flag;
- период проверки — ориентировочно один–три дня;
- после проверки готовится отдельное решение о production-релизе.

Риск доступности preview из интернета принят владельцем для этого короткого
этапа. Это решение не переносится автоматически на production.

## 4. Feature flags и kill switch

Плавающий UI запрашивает runtime-статус, а chat API отвечает только при:

```text
AI_WIDGET_PILOT_ENABLED=true
```

Для получения ответов дополнительно обязательны:

```text
AI_WIDGET_GATEWAY_URL=http://127.0.0.1:<port>
AI_WIDGET_GATEWAY_SECRET=<server-only>
```

Если `AI_WIDGET_PILOT_ENABLED=false`:

- status API возвращает `enabled: false`, и UI не показывается;
- API отвечает `404`;
- gateway не вызывается;
- fallback не создаёт заявку и не включает внешний канал.

Если flag включён, но gateway URL или secret отсутствует, интерфейс остаётся
видимым для проверки, а отправка вопроса получает нейтральный `503`.

`AI_WIDGET_PILOT_ENABLED=false` — основной kill switch.
После изменения server env достаточно перезапуска процесса; повторная сборка
статических маркетинговых страниц для скрытия UI не требуется.

## 5. UI и маршруты

### UI

Плавающий client-компонент монтируется в общем layout:

- виден справа снизу на маркетинговых и demo-страницах preview;
- скрыт в `/admin` и служебных интерфейсах;
- открывается боковой панелью без перехода на другую страницу;
- сворачивается обратно в плавающую кнопку;
- сохраняет текущую сессию при навигации по сайту;
- на мобильном занимает безопасную часть экрана и не перекрывает навигацию;
- показывает явную маркировку «закрытый тест»;
- не предлагает реальные цены и не обещает действия менеджера.

### Server API

`GET /api/demo/ai-widget/status`

- возвращает только runtime-состояние feature flag;
- всегда использует `no-store`;
- не раскрывает gateway URL, secret или сведения о модели.

`POST /api/demo/ai-widget/chat`

- доступен только при `AI_WIDGET_PILOT_ENABLED=true`;
- проверяет `Origin`;
- принимает JSON фиксированной схемы;
- ограничивает размер сообщения и истории;
- передаёт gateway только текущий безопасный контекст;
- возвращает streaming-ответ;
- не пишет текст сообщения в operational log.

`POST /api/demo/ai-widget/lead-simulate`

- требует отдельного явного согласия;
- требует имя, контакт, объект и содержательную задачу;
- работает только с локальным симулятором;
- всегда маркирует результат как `TEST`;
- не использует MAX, email, production registry и `/api/lead`.

## 6. Сессии и данные

В текущем UI-каркасе контекст живёт только в памяти открытой вкладки и не
записывается в localStorage, SQLite или аналитику.

На следующем gateway-этапе:

- анонимная диалоговая сессия — максимум 24 часа;
- активный контекст хранится server-side;
- полный transcript по умолчанию не сохраняется;
- отдельно маркированный синтетический QA transcript — максимум 7 дней;
- operational logs без PII и текста — максимум 14 дней;
- контакт, госномер и текст сообщения не попадают в аналитику;
- cleanup запускается по расписанию и проверяется отдельным тестом.

## 7. Ограниченный gateway

Gateway разрешает только:

```text
faq_lookup
knowledge_lookup
```

`lead_simulate` остаётся выключенным до отдельного этапа; намерение передать
обращение получает явное сообщение, что данные не сохранены и никто не
уведомлён.

Запрещены:

- terminal/exec и filesystem;
- browser/computer control;
- Codex и другие агенты;
- OpenClaw `main`;
- произвольная сеть;
- реальные CRM/MAX/email;
- команды парковочному оборудованию;
- чтение других сессий и заявок.

Gateway принимает запросы только с loopback и с отдельным server-to-server
secret. Ollama не публикуется наружу.

Локальный прототип реализован в
`scripts/run_ai_widget_pilot_gateway.py`. Точные FAQ, security-ответы и границы
знаний возвращаются детерминированно. Модельный ответ сначала полностью
проверяется Fact Gate и только затем передаётся сайту; при недоступной модели
gateway возвращает `503`, а не имитирует содержательный ответ.

При старте gateway прогревает `qwen3.6:27b` до объявления readiness и передаёт
Ollama `keep_alive=2h`. Secret читается из server env или указанного env-файла
без shell-выполнения его содержимого.

## 8. Защитные ограничения API

- allowlist `Origin`;
- request ID без PII;
- временный preview-limit: 10 запросов в минуту на адрес в памяти процесса;
- до VPS-релиза — перенос rate limit во внешний или persistent storage;
- идемпотентность будущего `lead-simulate`;
- timeout и отмена generation;
- лимит длины ответа;
- plain-text/Markdown sanitization;
- запрет произвольного HTML;
- нейтральная ошибка без внутренних путей, prompt и названий файлов;
- audit только для tool action, без текста диалога.

## 9. UI закрытого пилота

Минимальный интерфейс:

- плавающая кнопка справа снизу на всех разрешённых страницах;
- приветствие и граница возможностей;
- быстрые безопасные вопросы;
- потоковый ответ;
- кнопка остановки генерации;
- явный fallback «перейти к контактам»;
- отдельный consent flow тестовой карточки;
- кнопка очистки текущего диалога;
- отметка времени истечения сессии;
- предупреждение не вводить реальные персональные данные в закрытом тесте.

Отдельная страница и дополнительный логин внутри виджета не создаются.

## 10. Acceptance gate

До показа владельцу должны пройти:

1. unit tests origin, loopback gateway, size limits и kill switch;
2. тест отсутствия UI/API при выключенном flag;
3. browser smoke плавающей кнопки на маркетинговых и demo-страницах;
4. browser smoke отсутствия виджета в `/admin`;
5. открытие, сворачивание и сохранение диалога при навигации;
6. streaming smoke через loopback gateway;
7. 26 точных FAQ-шаблонов;
8. price, prompt injection, PII и false handoff regressions;
9. lead simulator без внешней отправки;
10. desktop/mobile/a11y review;
11. cleanup 24h/7d/14d;
12. подтверждение, что Метрика, MAX и production registry не задействованы.

## 11. Граница этапа

`AI-WIDGET-1` заканчивается закрытым test-only стендом на Mac Studio.

Он не разрешает:

- перенос на VPS;
- автоматический перенос открытого preview-доступа на production;
- реальный lead handoff;
- подключение MAX;
- использование рабочего OpenClaw;
- включение без отдельной приёмки директора.
