# РОСПАРК — публичный SEO/GEO baseline

Дата проверки: 2026-07-23
Связанный roadmap: `docs/site/SITE_DEVELOPMENT_ROADMAP_20260723.md`
Контур: публичный production и локальный код, только read-only
Статус: публичная техническая часть завершена; права в Google и Яндексе
подтверждены; начальный срез кабинетов снят; sitemap отправлен в оба кабинета,
новые данные обрабатываются.

## 1. Назначение и границы

Документ фиксирует фактическую исходную точку после Demo Release v1:

- доступность индексируемых URL;
- `robots.txt` и sitemap;
- canonical, metadata, H1 и JSON-LD;
- границы индексации demo и quiz;
- наблюдаемую публичную поисковую выдачу;
- пакет данных, который нужно получить из Google Search Console и Яндекс
  Вебмастера.

Публичная выдача не показывает точное число проиндексированных URL и не
заменяет данные поисковых кабинетов. В ходе проверки не изменялись код,
production, Nginx, DNS, sitemap, metadata и настройки поисковых систем.

## 2. Краткий вывод

Техническая SEO-основа сайта в рабочем состоянии:

- `robots.txt` разрешает обход и ссылается на актуальный sitemap;
- sitemap содержит 75 уникальных URL на едином `www` origin;
- все 75 URL отвечают `200`;
- среди URL sitemap нет `noindex`;
- у всех 75 страниц есть `title`, `description`, один H1 и JSON-LD;
- внутренние demo-сценарии и `/quiz` исключены из sitemap и закрыты от
  индексации;
- `/demo` остаётся индексируемым коммерческим хабом.

Обнаружены два ограниченных технических расхождения:

1. HTTPS-версия без `www` отвечает `200`, а не перенаправляет на `www`.
   Canonical указывает на `www`, но постоянный redirect был бы сильнее и
   устранил бы доступность дубля.
2. Страницы `/privacy` и
   `/soglasie-na-obrabotku-personalnyh-dannyh` наследуют metadata главной
   страницы, не имеют собственного canonical и образуют группу одинаковых
   `title`.

Главный оставшийся пробел — не техническая доступность сайта, а отсутствие
подтверждённых и накопленных данных Search Console и Яндекс Вебмастера.
Resources созданы, права подтверждены. Google сообщает, что данные
обрабатываются и станут доступны приблизительно через день. Яндекс принял
ресурс, но новая статистика ещё не сформирована. Проверенный sitemap отправлен в
оба кабинета 2026-07-23: Google ожидает первое чтение, Яндекс поставил файл в
очередь. До обработки отчётов нельзя достоверно утверждать, сколько страниц уже
проиндексировано, какие запросы получают показы и почему поисковик исключает
отдельные URL.

## 3. Проверенный публичный контур

### 3.1. Host и redirect

| Запрос | Результат | Оценка |
|---|---|---|
| `http://роспарк.рф/` | `301` на HTTPS без `www` | HTTPS включён |
| `https://роспарк.рф/` | `200` | доступен дубль origin |
| `http://www.роспарк.рф/` | `301` на HTTPS `www` | HTTPS включён |
| `https://www.роспарк.рф/` | `200` | основной origin |

Обе HTTPS-версии показывают текущий сайт. Canonical главной страницы у обеих
версий ведёт на:

```text
https://www.xn--80aukedde.xn--p1ai
```

Задача `SEO-CANONICAL-001`: после отдельного согласования настроить на Nginx
постоянный redirect с HTTPS non-`www` на соответствующий HTTPS `www` URL,
сохраняя path и query string. Перед изменением нужны backup конфигурации,
`nginx -t`, smoke и rollback. Эта задача не требует менять приложение.

### 3.2. robots.txt

Публичный файл:

```text
User-Agent: *
Allow: /
Sitemap: https://www.xn--80aukedde.xn--p1ai/sitemap.xml
```

Оценка: корректно для текущей открытой индексации. Чувствительные и
непредназначенные для поиска маршруты закрываются через metadata `noindex`, а
не только через robots.

### 3.3. Sitemap

Фактический результат:

```text
URL всего:                 75
уникальных URL:            75
URL на www origin:         75
URL с lastmod:             56
HTTP 200:                  75
не-200:                     0
```

Отсутствие `lastmod` у части статических страниц само по себе не считается
ошибкой. Для страниц с `lastmod` остаётся отдельная задача: не использовать
filesystem mtime как редакционную дату и хранить подтверждённые даты публикации
и обновления контента.

### 3.4. Полный HTML-аудит URL из sitemap

| Проверка | Результат |
|---|---:|
| Ошибки загрузки | 0 |
| Не-200 ответы | 0 |
| `noindex` внутри sitemap | 0 |
| Страницы без `title` | 0 |
| Страницы без `description` | 0 |
| Страницы с количеством H1 не равным одному | 0 |
| Страницы без JSON-LD | 0 |
| Страницы без canonical | 2 |

Canonical отсутствует у:

```text
/privacy
/soglasie-na-obrabotku-personalnyh-dannyh
```

Эти же страницы наследуют title главной:

```text
РОСПАРК — автоматизация парковок нового поколения
```

Локальная причина подтверждена: обе страницы не экспортируют собственный
`metadata` и наследуют root metadata из `app/layout.tsx`.

Задача `SEO-META-LEGAL-001`: добавить обеим юридическим страницам
уникальные `title`, `description` и self-canonical. Это малое изменение кода,
но выполнять его нужно отдельным принятым блоком с typecheck, lint, build и
проверкой сгенерированного HTML.

## 4. Граница индексации demo и служебных страниц

| URL | HTTP | Robots metadata | Sitemap | Оценка |
|---|---:|---|---|---|
| `/demo` | `200` | индексируем | включён | правильно |
| `/demo/gostevaya-zayavka` | `200` | `noindex, nofollow, nocache` | исключён | правильно |
| `/demo/web-skidki` | `200` | `noindex, nofollow, nocache` | исключён | правильно |
| `/demo/vladelec-parkovki` | `200` | `noindex, nofollow, nocache` | исключён | правильно |
| `/demo/arendar/demo-01` | `200` | `noindex, nofollow, nocache` | исключён | правильно |
| `/quiz` | `200` | `noindex, follow` | исключён | правильно |

Не нужно добавлять внутренние demo-кабинеты в sitemap. Отсутствие canonical у
части `noindex` demo-страниц не является текущим приоритетом: важнее сохранить
их закрытыми и не создавать индексируемые token/user-specific URL.

## 5. Публичная поисковая видимость

Проверены выборочные запросы:

```text
site:роспарк.рф
site:xn--80aukedde.xn--p1ai
"РОСПАРК" автоматизация парковок
"роспарк.рф"
```

В публичной выдаче обнаруживаются:

- новая главная на `www`;
- `/resheniya` и несколько новых страниц ролей/решений;
- отдельные страницы кейсов и оборудования;
- старый результат корня без `www` с устаревшим сниппетом;
- внешний результат РОСПАРК на Rutube.

Выборочные узкие `site:`-запросы по `/demo`, `/stati`, `/keysy` и
`/oborudovanie` не дали стабильного набора результатов в использованном
публичном поисковом proxy. Это не доказывает отсутствие страниц в индексе:
операторы `site:` дают неполную и меняющуюся выборку.

Практический вывод:

- поисковые системы уже обнаруживают новый сайт;
- признаки старого non-`www` результата сохраняются;
- точный индекс, выбранные canonical и поисковый спрос необходимо получить из
  кабинетов.

## 6. Пакет Google Search Console

Нужен владелец или пользователь с доступом к property сайта. Никакие изменения
в кабинете не выполнять до фиксации исходного состояния.

### 6.1. Текущее состояние аккаунта

Read-only проверка 2026-07-23 показала:

- пользователь авторизован;
- создана Domain property `роспарк.рф`;
- Google verification TXT-запись добавлена на корневой домен;
- запись подтверждена на авторитетных DNS REG.RU, системном resolver, Google
  Public DNS и Cloudflare DNS;
- право собственности успешно подтверждено в Search Console;
- обзор, эффективность, индексирование и качество показывают «Данные
  обрабатываются, повторите попытку приблизительно через день»;
- `https://www.роспарк.рф/sitemap.xml` отправлен 2026-07-23;
- интерфейс подтвердил «Файл Sitemap отправлен»;
- первоначальный статус строки — «Не получено», выявлено 0 страниц и 0 видео;
  это считать ожиданием первого чтения, а не результатом обработки;
- в коде приложения не обнаружен `google-site-verification`.

DNS домена обслуживается:

```text
ns1.reg.ru
ns2.reg.ru
```

Выбранный вариант — Domain property для `xn--80aukedde.xn--p1ai` с
подтверждением отдельной TXT-записью в DNS. Domain property объединит данные
HTTP/HTTPS, `www` и non-`www`. Не удалять TXT после успешного подтверждения:
поисковая система может периодически повторно проверять права.

## 7. Пакет Яндекс Вебмастера

### 7.1. Текущее состояние аккаунта

Read-only проверка 2026-07-23 показала:

- пользователь авторизован;
- создан сайт `https://www.роспарк.рф/`;
- Yandex verification TXT-запись первоначально добавлена на корневой домен;
- Яндекс вернул «Нет записи с ключом для подтверждения», поскольку проверяется
  конкретный `www`-host;
- отдельная TXT с тем же Yandex verification value добавлена на subdomain
  `www` и видна через `ns1.reg.ru`, `ns2.reg.ru`, системный resolver, Google
  Public DNS и Cloudflare DNS;
- право успешно подтверждено, аккаунт получил роль «Владелец»;
- в сводке нет текущих ошибок и рекомендаций;
- массовые дубли title/description не обнаружены;
- новая статистика поиска и индексирования ещё не сформирована;
- раздел «Страницы в поиске» показывает 0 добавленных, 0 удалённых и отсутствие
  новых изменений;
- `https://www.роспарк.рф/sitemap.xml` добавлен 2026-07-23;
- статус — «Очередь на обработку»; интерфейс указывает срок до 1–2 недель;
- сводка сохраняет старую историю обхода 2024 года с legacy URL; её не считать
  состоянием нового сайта до свежего обхода;
- в коде приложения не обнаружен `yandex-verification`.

Предпочтительный стартовый URL:

```text
https://www.xn--80aukedde.xn--p1ai/
```

Яндекс считает `www` и non-`www` разными адресами. Для выбранного сайта
опубликована TXT на `www`; корневая запись оставлена. После подтверждения прав
отдельно проверить выбранное главное зеркало. Не удалять TXT после успешного
подтверждения: Яндекс периодически повторно проверяет права.

### 7.2. Проверить сайт и зеркало

- подтверждены ли права на HTTPS `www` и доступные варианты host;
- какой host Яндекс считает главным зеркалом;
- присутствует ли `sitemap.xml`, его статус и дата загрузки;
- корректны ли региональность и организация, если эти данные заведены;
- нет ли критических сообщений диагностики.

## 10. Критерий завершения SEO-OPS-001

Этап закрывается, когда:

- properties зарегистрированы и права подтверждены либо документирована
  причина использования другого владельца/аккаунта;
- получены агрегированные данные обоих кабинетов либо документирована причина
  отсутствия одного из них или ещё не накопленной истории;
- зафиксированы indexed/excluded и причины;
- проверены sitemap и выбранные canonical;
- сняты запросы и страницы входа за доступные периоды;
- отделены брендовые и небрендовые запросы;
- назначены владельцы кабинетов;
- создан приоритизированный backlog, основанный на данных, а не на
  предположениях;
- roadmap и changelog обновлены по итогам принятого блока.
