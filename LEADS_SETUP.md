# Заявки с сайта РОСПАРК: настройка и production smoke

Актуально для `POST /api/lead` и `lib/leads.ts`.

Сайт умеет доставлять одну заявку одновременно в несколько каналов:

- Email через SMTP;
- Telegram через Bot API;
- внутренний чат MAX через бота.

Заявка считается доставленной, если успешно сработал хотя бы один настроенный канал. Ошибки остальных каналов записываются в серверный лог. Если не сработал ни один канал, API возвращает ошибку `500`.

Публичный канал РОСПАРК в MAX и внутренний MAX-чат заявок — разные сущности. Переменные `LEAD_MAX_*` относятся только к внутренней доставке лидов.

## 1. Контракт формы и API

- Основной endpoint: `POST /api/lead`.
- Старый `POST /api/quiz` отключён и возвращает `410 Gone`.
- Обязательные поля: `name`, корректный российский `phone`, `consent: true`.
- Honeypot-поле `website` должно оставаться пустым.
- Формы передают контекст: `source`, `intent`, `product`, `packageName`, `sourceUrl`, `sourcePage`, `sourceSection` и UTM.
- Имя, телефон и другие персональные данные нельзя отправлять в аналитику.

Минимальный корректный payload:

```json
{
  "name": "TEST РОСПАРК",
  "phone": "+7 999 000-00-00",
  "consent": true,
  "message": "TEST — проверка доставки, реальным лидом не является",
  "source": "production-smoke",
  "intent": "lead-delivery-check",
  "sourcePage": "/contacts",
  "sourceSection": "ops:production-smoke"
}
```

Без `consent: true` endpoint возвращает `400` и не запускает доставку.

## 2. Переменные окружения

Минимум один канал должен быть полностью настроен. Секреты хранятся только в окружении сервера и не добавляются в Git.

### Email

- `LEAD_EMAIL_TO` — один или несколько получателей через запятую;
- `LEAD_EMAIL_FROM` — отправитель; если не указан, используется первый адрес из `LEAD_EMAIL_TO`;
- `LEAD_SMTP_HOST`;
- `LEAD_SMTP_PORT` — обычно `587` или `465`;
- `LEAD_SMTP_SECURE` — `true` для TLS на 465, обычно `false` для 587;
- `LEAD_SMTP_USER`;
- `LEAD_SMTP_PASS`.

Email-канал считается включённым, когда задан `LEAD_EMAIL_TO`. Если при этом SMTP настроен неполно, попытка доставки завершится ошибкой этого канала.

### Telegram

- `LEAD_TELEGRAM_BOT_TOKEN` — токен бота;
- `LEAD_TELEGRAM_CHAT_IDS` — один или несколько `chat_id` через запятую.

Обе переменные обязательны для включения канала. Активная реализация не передаёт `message_thread_id`, поэтому отдельная Telegram-тема сейчас не поддерживается.

### MAX

- `LEAD_MAX_BOT_TOKEN` — токен MAX-бота;
- `LEAD_MAX_CHAT_ID` — числовой ID внутреннего чата, куда поступают заявки.

Обе переменные обязательны для включения канала. Перед production smoke нужно отдельно проверить совместимость установленного `@maxhub/max-bot-api` с актуальным API MAX. Не следует считать наличие токена доказательством успешной доставки.

### Публичная ссылка Telegram

- `NEXT_PUBLIC_TELEGRAM_CONTACT_URL` — необязательная ссылка для публичных кнопок связи.

Это не канал доставки заявок. Переменная попадает в клиентскую сборку и не должна содержать секреты.

### Текущий rate-limit

Endpoint ограничивает один IP до 12 запросов за 60 секунд в памяти процесса. Это MVP-защита: она не распределённая, сбрасывается при перезапуске и сейчас не настраивается через env.

## 3. Локальная настройка

1. Скопировать `.env.example` в `.env.local` и заполнить только нужные каналы.
2. Не коммитить `.env.local`, токены и пароли.
3. Запустить `npm run dev` или production-preview через `npm run build` и `npm run start`.
4. Проверить форму на `/contacts` или `/quiz`.

Локальная отправка вызывает реальные внешние каналы, если в `.env.local` указаны рабочие реквизиты. Использовать её только с согласованными тестовыми получателями.

## 4. Разрешённый production smoke

Production smoke создаёт реальное сообщение во всех настроенных каналах. Выполнять его только после явного подтверждения владельца сайта и получателей.

До отправки зафиксировать:

- дату и согласованное окно проверки;
- ответственного исполнителя;
- владельца очереди лидов и резервного ответственного;
- ожидаемые каналы доставки;
- целевое время подтверждения получения;
- способ пометить и удалить/закрыть тестовую запись в CRM или реестре.

Пример команды — шаблон, не запускать автоматически:

```bash
curl -X POST 'https://www.xn--80aukedde.xn--p1ai/api/lead' \
  -H 'Content-Type: application/json' \
  -d '{
    "name": "TEST РОСПАРК",
    "phone": "+7 999 000-00-00",
    "consent": true,
    "message": "TEST — production smoke, реальным лидом не является",
    "source": "production-smoke",
    "intent": "lead-delivery-check",
    "sourcePage": "/contacts",
    "sourceSection": "ops:production-smoke"
  }'
```

Критерии успешного smoke:

1. API вернул `2xx` и `{ "success": true }`.
2. Заявка пришла хотя бы в один ожидаемый канал.
3. Для каждого настроенного канала отмечено: доставлено, не доставлено или не проверялось.
4. Нет дублей одной заявки в пределах одного канала.
5. Имя, телефон, источник, время и UTM отображаются корректно.
6. Ответственный подтвердил получение и тестовая запись помечена как `TEST`.
7. Серверный лог проверен на `[lead] delivery failures` и `[lead] submit failed`.

Ответ `success: true` подтверждает, что сработал минимум один канал, но не гарантирует доставку во все настроенные каналы. Каждый канал проверяется отдельно.

## 5. Операционная ответственность

До начала рекламного трафика заполнить и согласовать:

```text
Источник истины для лида (CRM/реестр):
Владелец очереди:
Резервный ответственный:
Рабочие часы и часовой пояс:
Целевое время первого контакта:
Канал аварийного уведомления:
Порядок обработки дублей:
Срок хранения тестовых заявок:
Дата последнего production smoke:
Результат по Email / Telegram / MAX:
```

Email, Telegram и MAX являются каналами уведомления, а не источником истины. Если CRM ещё нет, нужен хотя бы контролируемый реестр со статусом, ответственным и временем первого контакта.

Текущий аудит двух lead-контуров, рекомендуемая модель registry/outbox и
решения, которые должен принять владелец, записаны в
`docs/site/LEAD_OPS_002_DECISION_20260724.md`. До их подтверждения этот файл
описывает только существующую доставку уведомлений, а не замкнутый процесс
обработки лида.

## 6. Диагностика

- `400 Укажите имя` — поле `name` пустое.
- `400 Проверьте телефон` — номер не прошёл проверку российского формата.
- `400 Нужно согласие` — отсутствует строгое boolean-значение `consent: true`.
- `429` — превышено 12 запросов с одного IP за минуту.
- `500 Не удалось отправить заявку` — ни один канал не доставил сообщение или конфигурация отсутствует.
- `[lead] delivery failures` — часть каналов упала, но другой канал мог доставить заявку.
- `[lead] submit failed` — запрос завершился общей ошибкой.

Не публиковать содержимое серверных ошибок, токены, SMTP-пароли и персональные данные в issue, PR, чатах разработки или аналитике.
